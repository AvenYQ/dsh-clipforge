# 页面 UI 重构（2026-11-18）

范围：`client.js` 的表现层。后端接口、`index.js`、数据结构、localStorage 键、所有交互逻辑保持不变。

## 改了什么

**记号系统**
- 统一一套 token：底面/浮层/内嵌三级色，墨色四级，一个暖橙强调色（浅 `#bf4d21`，深 `#e8865a`），圆角 8/12/16，阴影两级。
- 字号 15 / 13.5 / 12.5 / 11.5，正文 13.5；数字全部 `tabular-nums`；等宽字体只留给时间码和文件名。
- 去掉所有硬编码颜色（旧版里的 `#0b1120`、`#475569`、`#f8fafc` 等），全部走主题 token，深浅色自动跟随。

**结构**
- 顶栏改为：品牌 + 当前任务（过长省略）+ **步骤轨** + 模式/操作。步骤轨是唯一进度语言，完成打勾、当前高亮、窄屏只留当前一步。
- 两栏改为「素材 / 剪辑与导出」两组，卡片编号 ①–⑥ 连续；文稿台 ① 输入 ② 原文 ③ 分析，① 常驻。
- 卡片从「边框盒 + 大写等宽小标签」改成「浮层 + 圆角 + 留白」，卡片有三态：完成（绿）、进行（橙环）、待办（弱化）。

**一屏一个焦点**
- 主按钮随阶段移动：未解析时「解析」实心，解析后转幽灵；下载完成前「下载」实心，完成后转幽灵；有选区后「截取 MP4」实心，「生成 GIF」「试播」「循环」「吸附」全部降级为次级/开关态。
- 开关类按钮改用 `.is-on` 强调底色，不再和主按钮抢同一个实心橙。

**空态与等待**
- 六处空态统一成虚线框 + 图标 + 一句引导；未下载时播放器只留浅底空态，时间码条、快捷键条、选区面板整体收起，不再出现「一排禁用控件」。
- 下载进度条改 4px 圆角、百分比与大小右对齐；产物列表、拼接队列统一行高。

**文案**
- 清掉控制台话术：`STREAM_SRC // IDLE`、`TRACKS`、`READY`、`VIEW_IDLE`、`CH_01 · AUTO`、`ENGINE · WHISPER LOCAL`、`STAGE: 2/16 · CLIPS`、`BY SECTION`。
- 文稿模式换多行输入框，去掉视频站点的支持说明与标签。

## 修掉的老问题
1. 文稿台编号跳号、① 不常驻 → 现在两个模式都从 ① 开始连续编号。
2. 清空后回到初始态（`clearBoard` 已复位模式、正文、队列、产物与 localStorage）。
3. 文稿台有一批类名（`wb-quote`、`wb-mm-line`、`wb-reader-source`、`wb-out-*`）此前根本没有样式，现在是完整的一套。

## 2026-11-19 修正：侧栏收起后重叠、且找不到展开入口

根因：面板活在主区域的槽位里，宽度比窗口窄（打开侧栏时约少 260–310px），但断点写的是 `@media`，跟的是**窗口**宽度。窗口 1258 时面板实际只有 973，CSS 却以为有 1258，于是两栏和六个步骤的步骤轨照常展开，内容溢出槽位，压到左侧侧栏轨上，把展开按钮盖住。

修法：
1. `.wb-root` 设 `container-type: inline-size; container-name: wb`，全部宽度断点从 `@media` 改成 `@container wb`，按面板自身宽度切换（900 两栏→单栏、620 两栏输出→单栏、1000 收起非当前步骤、780 隐藏步骤轨、640 收紧顶栏）。
2. 根节点补 `width: 100%; max-width: 100%; min-width: 0; overflow: hidden`，顶栏去掉 `sticky`，各横向容器补 `min-width: 0`，任何情况下都不许画出自己的槽位。

另：侧栏开关在 DSH 里的默认快捷键是 ⌘B（`sidebar.left.toggle`），即使按钮被挡住也能靠它回来。

## 2026-11-19 修正之二：macOS 红绿灯压住品牌区

macOS 上侧栏收起时，布局给侧栏的宽度是 0（见 layout 里 `collapsedWidth = drawer || darwin || windowsTitlebar ? 0 : 56`），面板直接贴到窗口左边，红绿灯就画在面板顶栏上。

修法：面板挂载时量自己离窗口左边的距离，`data-platform` 为 darwin 且不足 78px 时，按差值给顶栏加左内边距；窗口缩放、侧栏开合同步复测（`ResizeObserver` + `resize`）。侧栏展开时面板左移已超过 78px，自动不加。

## 2026-11-19 修正之三：侧栏收起时顶栏让位（最终方案）

前两版都不对：先是硬编码 78px（方向、数值都错），再是量 rect 后补 padding（布局跳变在先，等于「先左后右」）。

最终做法——用框架发布的带宽，纯 CSS，无 JS：

```css
.wb-top {
  padding: 0 20px 0 calc(20px + var(--dsh-frame-leading-clearance, 0px));
  transition: padding-left var(--ds-transition-duration-slow, 300ms) var(--ds-ease-in-out, cubic-bezier(.4, 0, .2, 1));
}
```

- 目标值由 DSH 依布局状态直接写出（收起时 160px，全屏 84px，非 darwin 为空 → 0px），不是测出来的，所以不存在「先跳到左边再补」。
- 过渡曲线与时长跟侧栏列收放用的是同一条 token（`--ds-transition-duration-slow` / `--ds-ease-in-out`），两者叠加后位移单调。

实测（1318×800，侧栏 264 收起）：品牌起点 284 → 180，约 300ms，逐帧递减无回摆；展开反向下单调递增。收起后品牌距红绿灯右缘 72px、距开关座右缘 116px，实测相交面积为 0。

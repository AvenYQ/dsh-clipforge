## P0：会丢数据或让任务卡死

**1. `index.json` 写坏后，历史任务会被清空**
- 位置：`index.js` 第 256 行（写入）、第 908 行（读取）。
- 现象：`persist` 直接覆盖写 `index.json`，不是原子写入。如果写到一半进程被杀（比如 touch patch 重载、崩溃），文件就只剩半截。重启时 `JSON.parse` 失败，错误被 `.catch(() => {})` 静默吞掉，`jobs` 为空。之后下一次 `persist` 会用这个空列表覆盖文件。
- 后果：全部历史任务被清空，且没有任何提示。
- 修法：
  1. 改为原子写：先写 `index.json.tmp`，再 `rename` 覆盖。
  2. 读取失败时，把坏文件改名为 `index.json.bad-<时间戳>` 留作备份，并打 warn 日志。
  3. 读取失败后不允许用空列表覆盖原文件。

**2. 热重载时，最后 300ms 内的改动会丢失**
- 位置：`index.js` 第 909–911 行。
- 现象：effect 的清理函数只做了 `clearTimeout(saveTimer)`，没有把待写的数据落盘。你每次改宿主代码都要 touch patch 触发重载，正好会走到这条路径。
- 修法：清理时如果有待写数据，立即同步写一次（`fs.writeFileSync` 配合 tmp + rename）。

**3. 下载卡住后永远停在"下载中"，同一个链接也无法重新下载**
- 位置：`lib/media.js` 第 451–472 行；`index.js` 第 432–435 行。
- 现象：
  - `download()` 调用 `run()` 时没有设超时。
  - 变量 `last` 记录了最后一次进度时间，但后面从未读取。看起来本来打算做卡死检测，但没写完。
  - 函数签名里的 `signal` 参数也没有用上。
  - yt-dlp 一旦卡住（网络断开、等待输入），任务就一直处于 `downloading`。而 `api.download` 的去重逻辑会把这个卡住的任务当成"已有任务"直接返回。
- 后果：同一个链接重启宿主之前都无法重新下载。
- 修法：
  1. 让 `run()` 支持 `signal`，收到中止信号时 kill 子进程。
  2. 实现卡死检测：90 秒内没有新的进度行，就判定为卡死并 kill。
  3. 去重时排除超过 N 分钟没有进度的任务。

**4. 重启后去重失效**
- 位置：`index.js` 第 235–255 行。
- 现象：`persist` 没有保存 `audio`、`quality`、`heights`、`hasSubtitles` 这几个字段。重启后 `job.audio` 是 `undefined`，第 433 行的 `job.audio === Boolean(audio)` 永远不成立。
- 后果：重启后再贴同一个链接，会再下载一份。
- 修法：把这几个字段加进持久化的字段列表。

**5. 没有取消功能，也没有并发上限**
- 位置：`index.js` 全部 `api.*` 方法；`lib/media.js` 第 119 行的 `run()`。
- 现象：
  - 同时点 3 个视频的"提取文案"，会同时跑 3 个 whisper 和 3 个 ffmpeg 抽音轨，Mac mini 会被跑满，界面跟着卡。
  - `remove()` 只从 Map 里删除记录，后台进程照样继续跑。
- 修法：
  1. 加一个简单的分类型信号量：下载最多 2 个，ffmpeg（GIF、切片、拼接）最多 2 个，whisper 最多 1 个。超出的任务进入排队，界面显示"排队中（第 n 位）"。
  2. 每个任务保存一个 `AbortController`。新增 `api.cancel({ id, kind })`；`remove()` 时先取消正在跑的进程。

## P1：安全

**6. 本机接口可以被任意网页触发（CSRF）**
- 位置：`index.js` 第 73 行的 `readBody` 和第 956 行；`dsh-reader/index.js` 中的同名函数。
- 现象：服务端不检查 `Content-Type`，也不检查 `Origin`。你在普通浏览器里打开的任何网页，都可以用 `fetch('http://127.0.0.1:3080/workbench/api/download', { method: 'POST', body: '{"url":"..."}' })` 发请求。请求体是 text/plain 时不会触发预检，服务端照样会解析执行。
- 可被触发的操作：
  - 下载任意链接
  - 用你**已登录的** ego 浏览器打开任意页面（`browserOpen`、`browserFetch`）
  - 调用系统 `open`
  - 让 reader 抓取任意 URL
- 说明：如果 dsh web 本身带有会话鉴权，这个风险会小很多，但建议在插件里自己兜底。
- 修法（两个包都要改，约 5 行代码，前端不受影响，因为前端已经在发 `application/json`）：
  1. POST 请求必须带 `Content-Type: application/json`，否则返回 415。
  2. 如果请求带有 `Origin` 头，它必须等于 `http://127.0.0.1:3080` 或 `http://localhost:3080`，否则返回 403。

**7. Cookie 文件可能混入其他站点的登录态，且权限过宽**
- 位置：`lib/cookies.js` 第 181 行、第 213 行。
- 现象：
  - 过滤条件用了 `cookie.domain.includes(host)`，这是子串匹配。例如 `x.com` 能匹配到 `box.com`、`netflix.com`。
  - ego 浏览器是登录过的，导出的 cookie 包含会话凭据。
  - 文件按默认权限 0644 写入，其他用户也可读。
- 修法：
  1. 改为后缀匹配：`d === host || host.endsWith('.' + d)`，其中 `d` 是去掉开头点号的 domain。
  2. `writeFile` 时传 `{ mode: 0o600 }`。`douyin.js` 中的 ttwid 文件同样处理。

**8. reader 的 docId 没有校验**
- 位置：`dsh-reader/lib/cache.js` 第 7–9 行。
- 现象：`id` 来自请求体，未经校验就直接拼进路径。
- 修法：入口处校验 `/^[a-f0-9]{16}$/`，不匹配直接拒绝。

## P1：功能上的实际 bug

**9. 浏览器嗅探实际上只认抖音**
- 位置：`lib/sniff.js` 第 150–151 行；`lib/media.js` 第 946 行。
- 现象：
  - 嗅探只匹配 `mime_type=video_mp4` 和 `media-video` 这两种 URL 特征，这是抖音特有的格式。
  - `downloadSniffed` 把 Referer 写死为 `https://www.douyin.com/`。
  - 但现在抖音已经改走 `douyin.js` 的纯 HTTP 解析了。`probe` 对所有站点失败时都返回 `canSniff: true`，用户在微博、小红书等站点点"嗅探"时，基本都会得到"没拦到视频流"。
- 修法：
  1. 嗅探改为通用规则：按 response 的 `mimeType` 以 `video/` 开头，或 URL 中包含 `.mp4`、`.m3u8`、`.m4s` 来识别。按 Content-Length 或码率参数选出最大的一条。
  2. Referer 改为页面自身的 origin（`sniffed.url`）。
  3. 遇到 m3u8 时交给 ffmpeg 或 yt-dlp 下载，不要用 curl 直接拉。

**10. 长视频的说话人识别会静默失败**
- 位置：`lib/nlp.js` 第 115–132 行。
- 现象：所有字幕条目被一次性塞进一个 prompt，而 `maxTokens` 是 4096。每条输出 `{"i":123,"s":"A"},` 大约占 10 个 token，超过约 400 条时输出会被截断，JSON 不完整，`extractJson` 返回 null，于是说话人标签直接不显示，也没有任何提示。
- 修法（二选一）：
  - 按 150 条一批处理，批与批之间带上前一批最后 10 条作为上下文，保证说话人代号一致。
  - 改为让模型只输出"换人发生在第几条"（如 `[1, 37, 90]`），输出量小一个数量级。

**11. whisper 的语言判断太粗糙**
- 位置：`lib/media.js` 第 649 行。
- 现象：只要标题或描述里出现任何一个汉字，就强制使用 `-l zh`。B 站搬运的英文视频标题通常是中文，会被当成中文来转写，结果是乱码或"翻译腔"。
- 修法：默认用 `-l auto`。只有字幕或描述中的 CJK 占比超过 0.5，且平台是国内站点时，才指定 zh。

**12. 在 Finder 中显示的永远是最新那个文件**
- 位置：`index.js` 第 865–879 行。
- 现象：`reveal` 取的是 `job.gif` / `job.clip`，也就是最近一次生成的产物。在历史列表里点一个旧 GIF 的"在 Finder 中显示"，打开的却是最新的那个。
- 修法：接口增加 `filename` 参数，到 `gifs`、`clips`、`merges` 数组里按文件名查找。

**13. Range 请求的后缀写法处理错误**
- 位置：`index.js` 第 120–121 行。
- 现象：`bytes=-500` 的含义是"最后 500 字节"，现在被解析成"第 0 到 500 字节"。Safari 和部分播放器会发这种请求。
- 修法：当 `match[1]` 为空时，`start = size - Number(match[2])`，`end = size - 1`。

**14. 打包清单漏了文件**
- 位置：`package.json` 的 `files` 字段。
- 现象：清单里只列了 `lib/media.js`，没有 douyin、sniff、cookies、browser、nlp。现在用软链安装不受影响，但哪天改成 `dsh plugin add` 正式安装，加载时就会直接报错。
- 修法：改为 `"lib/*.js"`。

## P2：性能和体验

**15. 轮询的数据量过大**
- 位置：`index.js` 第 285–302 行；`client.js` 的轮询 effect（每 900ms 一次）。
- 现象：每次轮询都返回完整的文案正文、时间轴、最多 800 条 turns 和 4000 个 cues。一小时的访谈在翻译期间（通常要几分钟），每秒都要传几百 KB 重复数据，React 也跟着整页重算。
- 修法：
  1. `view()` 只返回状态字段和一个 `transcript.rev` 版本号，每次修改 transcript 时 rev 加 1。
  2. 前端发现 rev 变化时，再调用新的 `api.transcriptData({ id })` 拉取完整内容。

**16. GIF 压体积最多要渲染 8 次**
- 位置：`lib/media.js` 第 719–748 行。
- 现象：设置了目标体积时，会按 8 档参数从高到低逐档完整重渲染，每档都要重新生成调色板。一个 10 秒的 GIF 最坏要跑 8 遍 ffmpeg。
- 修法：
  1. 第一档渲染完后，根据"实际体积 ÷ 目标体积"估算面积和帧率需要缩小的比例，直接跳到最接近的档位，通常 2–3 次就能命中。
  2. 也可以先用低分辨率快速试渲一遍来估算体积。

**17. 抖音和嗅探下载时没有进度**
- 位置：`lib/media.js` 第 955 行、第 998 行。
- 现象：用 curl 下载时进度一直是 0%，界面只显示一段静止的文字。
- 修法：给 curl 加 `--progress-bar` 参数，在 stderr 中解析 `##.#%`。或者改用 Node `fetch` 加流式写入，自己计算 Content-Length 百分比。

**18. tmp 目录只增不减**
- 位置：`lib/media.js` 第 643–679 行、第 530–556 行。
- 现象：
  - whisper 失败时 wav 文件不会删除（一小时视频约 115MB）。
  - `sub-*.srt` 和 `*-asr.json` 从不清理。
  - 试播文件有保留 20 个的上限，但其他中间文件没有。
- 修法：
  1. 在 `transcribe` 里用 `try/finally` 删除 wav。
  2. 启动时清理 tmp 中超过 7 天的中间文件，`*.transcript.json` 除外。

**19. whisper 的配置没有吃满机器性能**
- 位置：`lib/media.js` 第 84–93 行、第 650–657 行。
- 现象：
  - 没有传 `-t` 参数，默认只用 4 个线程。
  - 模型按 small、medium、base 的顺序查找，两个都有时会选更小的 small。
  - `-np` 关掉了进度输出，界面看不到转写到哪里了。
- 修法：
  1. `-t` 设为 `os.cpus().length - 2`。
  2. 支持 `ggml-large-v3-turbo.bin`，并优先使用（中文效果明显更好，速度和 medium 接近）。
  3. 去掉 `-np`，加 `-pp`，解析 `progress = xx%`，回填到 `transcript.progress`。

**20. 翻译是串行的，失败的批次静默留空**
- 位置：`lib/nlp.js` 第 74–107 行。
- 现象：每批 24 条逐批串行处理。某一批两次都失败时，这 24 条译文直接留空，没有任何提示。
- 修法：
  1. 改为 3 批并发。
  2. 失败的批次拆成 8 条一组再重试一次。
  3. 最终统计 `missing` 数量写进 `translateNote`。

**21. ego 浏览器的路径写死在 profile 名下**
- 位置：`lib/browser.js` 第 228 行。
- 现象：路径中写死了 `profiles/desktop`。换 profile 或者 dsh-ego-browser 升级后目录结构变化，就会找不到浏览器。
- 修法：优先读环境变量 `DSH_EGO_BROWSER_CLI`。其次用 `import.meta.resolve('dsh-ego-browser/package.json')` 定位。都失败时再回退到写死的路径。

**22. 导图节点的 React key 可能重复**
- 位置：`client.js` 第 1754 行。
- 现象：key 用的是 `${depth}-${node.text}`。同一层级出现同名节点时 key 会重复，渲染可能错位。
- 修法：key 改为用路径下标拼接，例如 `0.2.1`。
